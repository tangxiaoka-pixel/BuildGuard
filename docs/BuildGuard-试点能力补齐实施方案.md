# BuildGuard 试点能力补齐实施方案

## 1. 目标与边界

本方案用于将当前的 BuildGuard 演示系统补齐为可开展项目试点的版本。目标不是一次性建设完整的生产级物联网平台，而是在保留现有实名制、考勤、设备开放接口、IoT 监测、平面图及 BIM 能力的基础上，补齐权限、数据留痕、基础配置、告警处置和考勤判定闭环。

本轮完成后，系统应具备以下特点：

- 企业、项目、班组长各自只能看到和操作授权范围内的数据。
- 人脸、身份证、平面图、BIM 等文件有统一归属、访问控制和删除记录。
- 设备、IoT 监测和视频 AI 的预警进入统一告警中心，可处理、可追溯。
- 考勤不再只是打卡流水，能够依据项目班次规则得到迟到、早退、缺卡、出勤时长等结果。
- 项目管理员能够通过项目配置集中开启模块、设置规则和查看待办。

本轮不包含：真实政府接口联调、工资发放、完整排班/请假/节假日体系、RVT 原生解析、设备远程控制、视频流存储平台和微服务拆分。这些能力保留扩展接口，待试点规则稳定后再建设。

## 2. 实施原则

1. **先权限，后功能。** 任何页面新增前先明确企业、项目、班组长的访问边界，前端菜单和后端接口同时校验。
2. **先统一数据底座，后扩展模块。** 文件、字典、日志、告警统一建模，避免各模块各自存储、各自展示。
3. **保留既有数据。** 现有工人、考勤、设备、上报和 IoT 数据迁移到新增结构或建立关联，不清库、不破坏当前演示数据。
4. **配置优先。** 工种、设备类型、区域类型、考勤规则、模块开关等从硬编码逐步改为配置。
5. **按项目灰度启用。** 新能力默认可由项目管理员配置开启，避免未使用塔吊或视频的项目出现无关菜单和待办。

## 3. 总体实施顺序

| 阶段 | 主题 | 产出 | 验收重点 |
| --- | --- | --- | --- |
| 第一阶段 | 权限与数据底座 | 项目级权限收口、文件中心、审计日志 | 越权页面和接口均不可访问；敏感文件不可直接公开访问 |
| 第二阶段 | 运行闭环 | 告警中心、设备离线判定、考勤规则与每日结果 | 设备离线能产生告警；打卡可判定迟到/早退/缺卡 |
| 第三阶段 | 配置与运营 | 数据字典、项目配置中心、人员上报状态、工作台待办 | 项目可配置模块与规则；待办可直接跳转处理 |
| 第四阶段 | 现场效率 | 批量操作、现场核验 H5 | 批量下发/上报可追踪；扫码核验不泄露敏感信息 |

建议按阶段上线，每完成一个阶段进行一次试点验收；下一阶段只在上一阶段通过后启动。

## 4. 第一阶段：权限与数据底座

### 4.1 项目级权限收口

#### 目标

解决项目用户能够进入企业级、以及通过直接输入 URL 或调用接口查看非授权数据的问题。

#### 账户范围与登录落点

| 账户类型 | 登录后默认进入 | 可访问范围 |
| --- | --- | --- |
| 平台超级管理员 | 平台级工作台 | 全部租户、企业和项目 |
| 企业级用户 | 企业级工作台 | 授权企业及其授权项目；拥有“全部项目”授权时自动覆盖后续新项目 |
| 项目级用户 | 指定项目工作台 | 仅被授权项目；不提供企业级入口 |
| 班组长 | H5 人员录入页 | 本人班组；仅新增和查看本班组人员必要信息 |

#### 实施内容

- 前端增加统一路由守卫：进入页面前校验账户类型、企业授权、项目授权和模块权限。
- 项目级用户登录后直接进入项目工作台；访问企业工作台、项目列表、企业汇总等地址时跳转至已授权项目，或显示“无企业级权限”。
- 左侧菜单由“层级 + 角色权限 + 项目模块开关”共同决定；不只隐藏菜单，也必须限制路由。
- 后端为所有带 `companyId`、`projectId`、资源 ID 的接口增加范围校验。资源 ID 查询后反查所属项目和企业，避免通过篡改请求参数越权。
- 统一返回 `403 无权限访问`，前端展示明确提示，不把数据为空伪装成无数据。
- 对 H5 接口增加班组边界校验：班组长只能新建、查看本人班组内的人员，不能借请求参数写入其他班组。

#### 验收标准

- 项目用户打开企业级 URL、刷新浏览器、手工访问接口，均不能获得企业汇总或其他项目数据。
- 企业用户仅能进入授权企业；无项目授权时不能进入具体项目。
- 班组长无法新增其他班组人员，且不能调用后台管理接口。

### 4.2 统一文件中心

#### 目标

将人脸、身份证正反面、附件、平面图、BIM 模型等上传文件统一管理，并对敏感文件实施访问控制。

#### 数据模型

新增 `file_resource`，核心字段如下：

| 字段 | 说明 |
| --- | --- |
| id / file_key | 文件唯一标识，业务表只保存此标识或资源 ID |
| original_name / extension / content_type / size | 原始文件信息 |
| file_category | 人脸、身份证正面、身份证反面、平面图、BIM、教育附件、其他附件 |
| business_type / business_id | 关联人员、项目、课程、设备等业务对象 |
| company_id / project_id | 数据归属范围 |
| sensitivity_level | 普通、受限、敏感 |
| storage_path / preview_path | 存储与预览路径 |
| uploaded_by / created_at / deleted_at | 上传和删除审计信息 |

#### 访问策略

- 人脸与身份证文件标为“敏感”，不直接暴露静态公网 URL；通过已登录的后端预览/下载接口鉴权后返回。
- 平面图、BIM、课程附件按项目权限控制；项目外用户不可预览。
- 上传时统一校验文件类型、大小、归属项目，并复用现有浏览器端图片压缩逻辑；服务器端继续限制超大文件。
- 删除采用逻辑删除；业务仍引用文件时禁止物理删除，管理员可在文件中心查看引用来源。

#### 页面与接口

- 项目级新增“文件中心”，可按用途、上传时间、业务对象筛选。
- 现有人员、平面图、BIM 上传页面改为统一上传组件，展示上传进度、缩略图、文件大小和替换操作。
- 提供文件上传、预览、下载、逻辑删除、业务关联查询接口。

#### 验收标准

- H5 人员录入、后台人员档案、平面图和 BIM 上传后均生成文件记录。
- 无项目权限的用户不能通过复制 URL 获取身份证或人脸文件。
- 删除文件后能查到删除人、时间和原业务关联记录。

### 4.3 操作审计日志

#### 目标

对关键业务操作留下可查询、可定位责任人的审计记录。

#### 记录范围

- 登录、退出、密码重置、账号启停、角色和项目授权调整。
- 人员新增、编辑、入场、退场、黑名单、人脸修改、区域权限调整。
- 教育台账通过/失效、设备确认/绑定/启停、设备下发与重试。
- 考勤补录、上报、重新上报、告警处理、文件上传和删除。

#### 数据模型与展示

新增 `audit_log`，记录操作人、角色、模块、动作、业务对象、企业/项目、操作前后摘要、IP、结果、失败信息和时间。

- 平台级可查看全局审计日志。
- 项目级仅查看当前项目日志。
- 日志支持按时间、操作人、模块、动作、结果、项目筛选。
- 对身份证号、手机号、请求体中的敏感字段进行脱敏后再入日志。

#### 验收标准

- 编辑人员、重置密码、确认设备、处理告警后，均能在日志中找到对应记录。
- 日志不可由普通用户修改或删除。

## 5. 第二阶段：运行闭环

### 5.1 统一告警中心

#### 覆盖来源

- 塔吊监测：超载、超幅、限位、风速、碰撞、离线等。
- 升降机监测：超载、超速、倾斜、门锁、人数、离线等。
- 扬尘噪音：PM2.5、PM10、噪音、风速、喷淋联动建议、离线等。
- 视频 AI：未佩戴安全帽、未系安全带、明火烟雾、人员闯入、危险区域停留等。
- 考勤设备与 IoT 网关：离线、未知设备、连续上报失败等。

#### 数据模型

新增 `alarm_record`：告警来源、设备类型、设备、项目、告警类型、级别、标题、内容、原始数据、首次发生时间、最近发生时间、状态、处理人、处理时间、处理说明、关联图片/视频文件。

状态为：待处理、处理中、已处理、已忽略。级别为：提示、一般、严重、紧急。

#### 页面与流程

1. 设备或 IoT 平台上报异常。
2. 系统写入告警；同设备同类型在设定时间窗口内合并计数。
3. 项目告警中心显示待处理告警，可筛选、查看原始数据、查看设备和现场点位。
4. 管理员填写处理说明并关闭或忽略；所有动作写入审计日志。
5. 企业工作台汇总所属项目的未处理告警；项目大屏显示严重与紧急告警。

#### 验收标准

- 模拟塔吊、扬尘、视频 AI、设备离线告警能统一出现。
- 处理后状态、处理人、说明和时间完整留痕。
- 从告警可跳转至设备详情、平面图/BIM 点位或原始 IoT 数据。

### 5.2 设备离线判定

#### 实施内容

- 所有接入设备统一维护最近签到、最近心跳、最近数据上报时间。
- 项目配置离线阈值，默认 10 分钟；不同设备类型可覆盖默认值。
- 定时任务每 1 分钟检查一次：超过阈值将状态设为离线，并且只生成一条未恢复离线告警。
- 设备恢复心跳后状态自动恢复在线，关闭或标记恢复对应离线事件。
- 待确认设备仍保存心跳和原始报文，但不归属项目；确认绑定后自动关联后续数据。

#### 验收标准

- 将设备最后心跳调整为阈值前，系统自动变为离线并生成告警。
- 同一离线周期不重复刷屏；恢复后设备状态和告警恢复时间正确。

### 5.3 考勤规则与每日考勤结果

#### 目标

在现有“考勤流水”和“每日考勤明细”基础上，增加可配置的班次与结果判定。

#### 首期规则范围

| 项目 | 首期支持 |
| --- | --- |
| 班次 | 一天最多两个时段，支持跨天班次 |
| 时间 | 上班、下班、最小有效出勤时长 |
| 容差 | 迟到宽限、早退宽限、缺卡判定时间 |
| 分配 | 项目默认规则，可按班组覆盖 |
| 结果 | 正常、迟到、早退、缺卡、旷工、加班、无排班 |
| 排除项 | 请假、节假日、复杂轮班暂不纳入首期自动计算 |

#### 数据模型

- `attendance_rule`：规则名称、项目、有效期、启用状态。
- `attendance_shift`：班次时段、跨天标记、宽限时间、标准工时。
- `attendance_rule_assignment`：规则分配到项目默认或班组。
- `attendance_daily_result`：人员、日期、班次、上班打卡、下班打卡、出勤分钟、结果、异常原因、关联原始考勤。

#### 页面与流程

- 在“考勤管理”下新增“考勤设置”。
- 项目管理员创建并启用规则，设置默认班次或分配给班组。
- 考勤数据写入后由定时任务或手动“重新计算”生成每日结果。
- 每日考勤明细从结果表展示：人员、班组、班次、每时段上/下班时间、出勤时长、出勤结果和异常说明。
- 保留原始打卡流水，不因规则调整而丢失；规则版本和计算时间可追溯。

#### 验收示例

默认班次设为 09:00 至 18:00，迟到宽限 10 分钟：

- 09:00 入场、21:00 离场：正常出勤，并标记 3 小时加班。
- 09:30 入场、18:00 离场：迟到。
- 09:00 入场、无离场：缺卡。
- 无有效入场记录：旷工或无排班，按人员是否已分配班次判断。

## 6. 第三阶段：配置与运营

### 6.1 数据字典与基础配置

平台级新增“数据字典”，用 `dict_type` 和 `dict_item` 管理编码、名称、排序、状态和适用范围。

首批接入字典：工种、参建单位类型、设备类型、区域类型、班组类型、教育类型、考勤异常原因、上报失败原因、告警类型、IoT 设备类别和项目模块类别。

现有表单中的硬编码下拉项逐步替换为字典接口；已有数据保留原值并通过编码映射兼容。

验收：平台管理员新增工种后，劳务工人录入及项目工作台工种分布可立即使用该工种。

### 6.2 项目配置中心

项目级新增“项目配置”，集中管理：

- 模块开关：实名制、安全教育、设备门禁、考勤、数据上报、塔吊、升降机、扬尘噪音、视频 AI、平面图、BIM。
- 考勤默认规则与离线阈值。
- IoT 网关和设备接入参数的展示入口。
- 安全教育有效期、设备下发前置条件等项目规则。
- H5 人员录入权限与班组长范围。

模块关闭后：左侧菜单、工作台卡片和普通业务入口隐藏；相关历史数据保留；接口拒绝新的业务写入，但设备原始数据仍可存入接入日志，避免数据丢失。

### 6.3 人员上报状态产品化

人员详情“上报记录”页签展示实名制上报状态、最后上报时间、平台响应、失败原因和重新上报按钮。

劳务工人列表增加可筛选的上报状态；批量上报后可查看成功/失败汇总。政府接口继续保持模拟模式，正式接口接入时替换适配器，不改变前端流程。

### 6.4 工作台待办

平台、企业、项目工作台增加统一待办卡片：待处理告警、待确认设备、待下发人员、安全教育未通过/即将过期、异常考勤、上报失败。

每张卡片点击后进入对应模块并自动带入筛选条件。待办数据按当前账户的授权范围聚合。

## 7. 第四阶段：现场效率能力

### 7.1 批量操作

在劳务工人列表支持勾选人员后执行：批量配置区域、批量下发设备、批量实名制上报、批量导出、批量入场/退场。

所有批量操作均提供“选择对象 - 预检查 - 结果预览 - 确认执行 - 结果明细”五步流程；失败项不影响成功项，并可单独重试。批量操作写入审计日志。

### 7.2 现场核验 H5

新增只读的现场核验 H5，面向项目管理员、安保人员等受授权现场人员。

- 支持扫码人员二维码或输入人员编号/手机号查询。
- 展示脱敏姓名、头像、工种、班组、参建单位、在场状态、安全教育状态、可进入区域、最近考勤和设备下发状态。
- 不展示完整身份证号、手机号、住址、身份证照片和银行卡信息。
- 核验页面与现有“班组长新增人员 H5”独立，避免录入权限与核验权限混淆。

## 8. IoT 平台与 KKOS 网关接入原则

KKOS 网关可以作为现场统一接入网关，但不是唯一设备实体。建议链路如下：

```text
塔吊 / 升降机 / 扬尘噪音 / 摄像机 / 考勤设备
                    ↓
             KKOS 网关或厂家云
                    ↓
              BuildGuard IoT 接入层
                    ↓
        原始数据、设备状态、监测数据、告警中心
                    ↓
        项目工作台 / 大屏 / 平面图 / BIM 点位
```

- 每台网关拥有唯一编码、项目归属和心跳状态；下挂设备必须拥有独立设备编码和设备类型。
- IoT 接入层保留原始报文，转换为统一的监测数据和告警模型；避免业务页面直接依赖某一厂家协议。
- 未注册设备或网关进入待确认状态，原始数据不丢弃；管理员确认项目、区域和设备类型后再正式归属。
- 平面图与 BIM 点位绑定的是“逻辑设备 ID”，不直接绑定厂商报文中的临时字段，后续换网关或换协议不影响点位。

## 9. 技术实施与发布要求

- 后端继续采用现有 Spring Boot 单体结构，按模块拆分服务、权限校验、定时任务和审计切面，不引入微服务。
- 前端继续使用 Vue 3，路由地址保持固定可刷新；新增页面纳入当前项目/企业上下文和菜单权限体系。
- 数据库采用渐进式升级：新增表、索引和迁移脚本；上线前备份当前 H2/线上数据库与上传文件目录。
- 线上部署采用先备份、后发布、健康检查、可回退的流程；上传文件目录不随前端发布清理。
- 每阶段完成后执行：关键接口测试、角色回归测试、上传测试、浏览器刷新测试、线上页面验收。

## 10. 阶段验收清单

### 第一阶段

- [ ] 项目用户不能进入企业级页面或取得企业级接口数据。
- [ ] 文件中心能管理人脸、身份证、平面图、BIM，敏感文件需权限访问。
- [ ] 关键人员、设备、账号、告警和文件操作均有审计日志。

### 第二阶段

- [ ] 塔吊、升降机、扬尘、视频 AI、设备离线告警统一进入告警中心。
- [ ] 设备超时无心跳自动离线，恢复后自动恢复状态。
- [ ] 可配置考勤班次；每日明细显示上下班、工时、迟到、早退、缺卡和加班。

### 第三阶段

- [ ] 工种及基础类型可由数据字典维护。
- [ ] 项目可独立开启/关闭监测模块和设置运行规则。
- [ ] 人员详情可查看、重试实名制上报。
- [ ] 工作台待办能跳转到对应待处理列表。

### 第四阶段

- [ ] 可批量配置权限、下发设备、上报和导出，结果可追溯。
- [ ] 现场核验 H5 可扫码查验且不泄露敏感信息。

## 11. 需在评审时确认的决策

1. 文件首期继续存放在当前服务器磁盘并通过文件中心管理，还是同步接入对象存储。建议首期使用当前服务器目录，试点稳定后迁移对象存储。
2. 告警中心首期是否将“异常考勤”作为正式告警来源。建议先作为待办统计，IoT/设备类告警先正式闭环，避免告警数量失控。
3. 考勤规则首期是否采用“项目默认规则 + 班组覆盖”。建议采用该方式，暂不做人员级、节假日和请假联动。
4. 班组长是否只保留 H5 人员录入权限。建议如此，PC 端项目管理仍由项目管理员负责。
5. 项目模块关闭后是否保留原始设备接入。建议保留接入日志和原始数据，但不展示业务菜单、不生成业务告警，方便后续重新开启。

## 12. 建议的执行起点

评审通过后，按以下顺序开始实施并每一小阶段发布线上供验收：

1. 项目级权限收口。
2. 统一文件中心。
3. 操作审计日志。
4. 统一告警中心与设备离线判定。
5. 考勤规则配置及每日考勤结果。
6. 数据字典、项目配置中心、人员上报状态和待办。
7. 批量操作与现场核验 H5。
